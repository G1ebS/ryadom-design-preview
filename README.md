# «Рядом»: три направления и объединение B+C

Откройте [интерактивную галерею](index.html). Слева доступен список из **46 экранов**; сверху можно переключить A, B, C или объединённый B+C, сохранив выбранный экран. По умолчанию открыт B+C: фильтры услуги, дня и времени из B находятся сверху, а результаты представлены карточками салонов из C. Переключатель **«Телефон / Компьютер»** показывает обе компоновки любого экрана. Внутри макета работают основные переходы и демонстрационные действия. Кнопки «Клиент», «Владелец», «Администратор», «Мастер» показывают разные кабинеты. Все данные в прототипе вымышлены и хранятся только в текущей вкладке.

## Чем различаются направления

| Критерий | A — «Забота по шагам» | B — «Найти своё время» | C — «Мои места» | B+C — «Время и места» |
|---|---|---|---|---|
| Первый вопрос интерфейса | Что человеку полезно сделать сейчас? | Когда ему удобно? | В какой знакомый салон он хочет прийти? | Какая услуга, день и время удобны? |
| Путь к записи | Задача → салон → услуга → мастер и время → итог | День и время → сравнение вариантов → условия → подтверждение | Салон → его услуги, визиты и награды → запись | Верхние фильтры → карточки салонов с ценой и временем → подтверждение |
| Навигация | Следующее действие и подсказки по шагам | Поиск, фильтры и результаты рядом | Постоянный контекст выбранного салона | Поиск плюс контекст выбранного салона |
| Плотная информация | Делится на шаги | Показывается в списке или временной сетке | Группируется вокруг салона | Сначала условия, затем содержательные карточки |
| Сильная сторона | Понятно новичку и редкому посетителю | Быстрое сравнение для занятого клиента | Быстрое возвращение постоянного клиента | Быстрый поиск без потери ощущения знакомого места |
| Компромисс | Для сравнения нужно больше переходов | Результаты и фильтры требуют внимания | Для сравнения салонов нужно выйти уровнем выше | Верхний блок занимает место на телефоне |

**Выбранное направление для обсуждения:** B+C по обратной связи: верхние фильтры поиска из B и карточки салонов из C. Исходные A, B и C сохранены рядом для сравнения.

## Как пройти сценарии

1. **Новая запись в B+C:** «Главная» → выбрать услугу, день и время → «Показать подходящие места» → карточка салона → «Выбрать время» → итог → подтверждение → запись. В A путь начинается с полезного действия, в B — с поиска времени, в C — с «Моих мест».
2. **Нет свободного времени:** «Время и мастер» → «Показать состояние без слотов» → «Сообщить об освободившемся времени» → предпочтения → предложение → принятие либо отказ. Альтернативный вход: «Карточка записи» → «Хочу прийти раньше». Текущая запись сохраняется до принятия нового времени.
3. **Работа салона:** переключите роль на «Владелец» или «Администратор» → «Живое окно» → цепочка из кандидатов → «Остановить это окно». Широкие версии календаря и CRM находятся под мобильным макетом соответствующих экранов.
4. **Роль мастера:** переключите роль на «Мастер» → свои назначения → исход визита. Управленческие разделы принадлежат владельцу и администратору.

В списке слева также показаны история, оценка, награды, акции, события, уведомления, CRM, услуги, график, аналитика, программы лояльности, партнёрства, сотрудники, журнал действий, создание салона и приглашение. Для управленческих разделов показаны структура и ключевые состояния; это дизайн-макеты, а не готовая бизнес-логика.

## Правила, которые отражены в макетах

- Запрос «Живого окна» не создаёт запись и не удерживает время.
- Предложение отправляется одному кандидату за раз, имеет срок действия, а доступность проверяется при принятии.
- Принятие предложения для уже существующей записи меняет её время, не создавая вторую запись.
- Перед записью видно цену после одной выбранной выгоды; оплата происходит в салоне.
- Остановка рабочего окна отзывает текущее предложение и прекращает цепочку для данного слота.
- Один человек может переключаться между клиентским и рабочим кабинетом; мастер видит ограниченный маршрут.

## Мини-гайд направления A

Экран mini-app показан в размере 390 × 844 px. Широкий режим рассчитан на просмотр около 1440 px: у клиента появляется постоянная навигация и боковой контекст, у сотрудников календарь и CRM раскрываются в рабочую сетку. Фон — тёплый светлый `#f8f8f3`, основной текст — `#23443c`, действие — `#276b56`, мягкая подложка — `#e8f4e9`. Типографика: Manrope с запасным Arial, заголовок мобильного экрана 27 px, основной текст 13–14 px, служебные подписи 10–12 px. Базовый внутренний отступ мобильного экрана 22 px; карточки с радиусом около 20 px; основная кнопка не ниже 48 px. Основное действие залито, вторичное имеет контур, текстовое действие используется для менее частого перехода; опасное действие красное и сопровождается экраном с последствиями. Подтверждение, предупреждение и ошибка получают отдельные состояния и текст, а не передаются одним цветом.

Из референсов взяты конкретные приёмы: от Linear — чёткая иерархия статуса и рабочего дня, от Attio — группировка данных клиента и отделение внутренней информации от клиентской. Их фирменные экраны и визуальные элементы не копировались.

## Допущения и вопросы

Статические примеры используют 29 сентября — 2 октября 2026 года, московское время, вымышленные салоны и клиентов. Доступность, очередь, цены, права доступа и уведомления не связаны с сервером. Для финального продукта надо уточнить реальные ограничения отмены и переноса, правила совместимости наград с услугами и партнёрствами, состав фильтров поиска и допустимые каналы уведомлений. В галерее тексты редактируются как HTML; ссылка на Figma не требуется по последней просьбе заказчика.

## Как поделиться

Это статический сайт: достаточно передать содержимое папки целиком или разместить её на любом статическом хостинге. Для пересылки без хостинга откройте `index.html` из архива; Интернет нужен только для необязательной загрузки шрифтов Google, при недоступности которых используется Arial. Локальный адрес `127.0.0.1` работает только на компьютере автора и не является публичной ссылкой.
